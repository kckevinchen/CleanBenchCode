Perturbations (adaptive only)

What changes between passes so the detector sees a slightly different view of the world. Prompt-ensemble injects the most signal for cell-local error types; row/column shuffles are mostly useful when column_mode = all.

Row duplication (only relevant when row_duplication is selected)

Whole-table recall-first pipeline: key-collision + normalisation + LLM canonicalisation + token-signature blocking + MinHash + sentence embeddings, all unioned and adjudicated by the LLM. Defaults configured in config/experiment.yaml; the only knobs exposed here are the operational dials below.

Cluster adjudication and per-column canonicalisation (when their toggles above are on) are driven through the shared Stopping rule above. With Kmax=1 each LLM call runs once; with Kmax>1 calls are repeated under the Good-Turing/Chao1 stop rule and unioned recall-first.

Multi-table cross-sheet (only relevant when inter_table_inconsistency is selected)

End-to-end pipeline triggered automatically when inter_table_inconsistency is in the selected error types and at least 2 CSV sheets share a workbook directory. Steps: priors → LLM-confirm groups → per-row violation detection (semantic LLM detector by default; switch to compiler+verifier for cheaper LLM spend). Outputs land in this run's multi_table_groups.jsonl + multi_table_violations.jsonl alongside the single-table findings. 


      

    


    
    

      

        
Discover relations multi-column · multi-row · multi-table

        

          One LLM call per (source, error_type). The model receives a
          schema digest plus a few sampled rows and enumerates the
          relations that govern the table — functional dependencies,
          calculation rules, cross-column constraints, business rules, and
          cross-table joins. Output: relations.jsonl + a
          self-contained dashboard. Single-column types (typos, formatting,
          missing values…) are out of scope here — use the detection
          launcher for those.

          Adaptive loop (Good-Turing multi-pass)
          

            With adaptive, each (source, error_type)
            arm runs multiple passes with different row-sample seeds and

          Aggregation pass (merge paraphrases)
          

            After discovery, cluster rules by
            (source, error_type, columns) and ask the LLM
            to partition each cluster into the smallest set of
            canonical rules. Multiple canonicals per cluster are
            supported - this only collapses paraphrases of the same
            constraint, never genuinely distinct rules. Originals are
            preserved in relations.jsonl.
          

          
          
        


        

          Validation pass (empirical pass-rates)
          

            After aggregation, ask the LLM to write a
            check(df) -> Series function for each rule
            (or refuse when not code-verifiable). Functions run in a
            restricted sandbox; per-rule pass-rates and sample
            violations land in relation_verifications.jsonl
            and surface as colored badges on each report card.

          Quality gates
          
          
          
          
          
          
          
          
Each kept table is written empty-free: all-empty columns are dropped, then any row containing an empty cell (incl. -, *, N/A sentinels) or an oversized cell is dropped. Tables whose cleaned shape falls outside the rows/columns windows, or that lose more than the oversized-row ratio to the cell-size gate, are rejected (and in grouped mode the whole workbook with them).

Chunk the CSV

              
Split each table into row-chunks. chunk_size = rows per call. With column_mode=single one call also scopes to one column at a time.

Phase A · per-type detection

              
One LLM call per (chunk, error_type). Each of the 20 error types has its own targeted prompt. Calls run concurrently against the endpoint pool.

              

                Single-Column (8)
                Multi-Column (6)
                Multi-Row (3)
                Multi-Table (3)

Phase A · deterministic clustering

              
Detections sharing the same row + overlapping columns merge into one cluster. Keeps evidence_count, union of columns, and the set of error types.

            

          


          
↓

Phase B · LLM synthesis (optional)

              
For every multi-type cluster, one extra LLM call picks a primary_error_type, classifies the rest as supporting, emits canonical explanation + fix + confidence, and flags is_likely_false_positive.

              
Skip via the --no-synthesis CLI flag.

GPT model

            
Azure-hosted GPT-5 family (configurable via model). Calls go through a pool with built-in concurrency and retries; reasoning_effort controls the thinking budget (low/medium/high).

          


          

            
column_mode

            
auto: dispatcher splits selected error types by scope — single-column types run with one call per (chunk, column), multi-column / multi-row / multi-table types run with the whole row visible per call.
single: one call per (chunk, column, error_type). Cheap; required by the single-column types.
all: one call sees every column; required for multi-column / multi-row / multi-table types.

          


          

            
Scopes

            
Pick which subset of the 20 error types to run. The four scopes — single-column, multi-column, multi-row, multi-table — correspond to the groups you see in the Error types fieldset.

          


          

            
Experiment mode

            
single: one pass per (chunk, error_type). Fast.
adaptive: Good-Turing / Chao1 multi-pass loop. Each (stop_scope, error_type) arm is tracked independently; the loop halts once every error_type's arms have all saturated under gt_target_missing_mass (or num_runs is reached). Use Stop scope to choose granularity (auto = pick by selected error types — column when single-column-only, column_pair when multi-column is included, csv when multi-row, multi_table when multi-table; column = per-(source, column, error_type); dataset = one arm per error_type; etc.).

          


          

            
Prompt ensemble

            
Adaptive mode only. On non-identity passes, an LLM rewriter generates a fresh variant of each per-type prompt. Adds prompt-level diversity to the coverage estimator.

          


          

            
Perturbations

            
Adaptive mode only. Row / column shuffles inject presentation noise across passes so the coverage estimator sees genuinely different detection pools.

          


          

            
Labelling + benchmark

            
From Runs, click Label on any run to open the per-cell annotation UI. Its Export dropdown writes a per-cell benchmark.jsonl (and a per-error-type bundle) ready for downstream eval.

          


          

            
SSH-safe jobs

            
Every job runs in its own session (setsid) and persists state to logs/jobs/*.json. Server restart or SSH drop won't kill a running detection; the Jobs tab marks recovered jobs and still lets you cancel them.
