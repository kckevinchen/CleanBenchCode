How to read these numbers

In adaptive mode we run the detector K times, perturbing the prompt or the row/column order each pass, then canonicalise every detection into a species (source, error_type, column, row). The counts nr below are how many species were seen in exactly r of the K runs. The two estimators turn those counts into a “how much are we missing?” number.

S_obs (observed species)
Count of distinct defect locations the detector flagged across all completed passes. Grows monotonically; a flattening S_obs curve is the main qualitative signal that coverage is saturating.
n1 / singletons · n2 / doubletons
Species seen in exactly 1 run (n1) or 2 runs (n2). Many singletons → the detector is noisy / unsettled and there is likely more to find; few singletons → every pass keeps surfacing the same defects, so coverage is probably close to complete.
GT missing mass
Good-Turing estimator of the probability that the next perturbed run surfaces a never-before-seen defect: n1 / Σr r · nr. Numerically equal to the detector's estimated miss probability per new draw. Adaptive mode stops once this drops below target_missing_mass (provided min_runs passes have completed).
Est. FN rate
Estimated fraction of defects the detector is missing overall, with a log-normal 95% CI. Headline answer to “how much should I trust this run?” Derived from Chao1: 1 - S_obs / S_est.
Chao1 total (S_est)
Non-parametric lower bound on the true number of defects in the data, computed from n1 and n2: S_est = S_obs + n12 / (2·n2) (with a bias correction when n2 = 0). The CI is log-normal on the hidden count S_est - S_obs.
Prompt column (progression)
seed means that pass used the hand-written error type definition; variant means an LLM rewrote description / notes / example first. Counts after the chip tell you how many types were successfully rewritten vs. fell back to the seed.

Rule of thumb. If GT missing mass keeps falling and S_obs flattens by run K, the detector has covered its addressable population. If GT missing mass is still large (> ~5%) at the cap, raise gt.num_runs or strengthen the perturbation (prompt_ensemble: true usually helps far more than row shuffling for cell-local errors).

Per-type saturation

Under the unified per-arm stop logic, each (stop_scope, error_type) pair is its own arm. A type becomes "saturated" once all of its arms cross the stop predicate (after at least min_runs passes). Saturated types are pruned from later passes — both detector calls and prompt variants — so cost shrinks pass-over-pass. The "Arms saturated" column tracks this at the finer arm grain.
