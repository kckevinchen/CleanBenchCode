Data-cleaning benchmark generation pipeline

From raw spreadsheet to labelled benchmark with a coverage estimate.

Input: CSV / spreadsheet files
One or many tables.
▼
1
Per-type LLM scan
One focused question per error type, per data chunk.
▼
2
Grouping & explanation
Merge overlapping findings into one candidate; LLM writes canonical explanation, suggested fix, confidence, and self-flags low-confidence cases.
▼
3
Relation discovery
LLM enumerates multi-column rules (e.g. Total = Qty × Price, ZIP determines State); each rule is validated row-by-row, violations enter the queue.
▼
4
Web verification
For named-entity candidates: web search + LLM verdict (confirmed wrong / looks correct / no evidence) using only the retrieved snippets.
▼
5
Human review
Reviewer labels each candidate in the web UI. Confirmed candidates form the benchmark; rejections are kept as hard negatives.
▼
Labelled benchmark
Confirmed errors + hard negatives, with a coverage estimate.
